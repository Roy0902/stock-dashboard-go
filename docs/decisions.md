# Engineering decisions

| ID | Date | Decision | Rationale | Consequence |
| :-- | :-- | :-- | :-- | :-- |
| D-1 | 2026-11-18 | New implementation lives in `stock-dashboard-go/` beside the existing Node build. | The original TypeScript app is finished work; the Go + React stack is a separate delivery. Nothing is deleted. | Two runnable apps share one spec. This one is authoritative for the new stack. |
| D-2 | 2026-11-18 | Go standard library router, no framework. | Six routes and one static handler do not justify a dependency. Go 1.22 patterns cover method and path matching. | Routing is visible in one file; less upgrade surface. |
| D-3 | 2026-11-18 | TanStack Query instead of `useEffect` polling. | Polling, stale handling, invalidation and error state are explicit and testable. | One runtime dependency, ~13 kB gzipped. |
| D-4 | 2026-11-18 | Custom SVG chart. | The approved plan requires a chart with a specific accessible name and no chart library budget. | Full control of `role="img"`, labels and responsive layout. |
| D-5 | 2026-11-18 | Both API keys required for `/api/quotes` and `/api/chart`. | Spec §3 says the missing-key message names both keys and appears when either is absent. | A partial configuration fails visibly instead of silently degrading. |
| D-6 | 2026-11-18 | `INTERNAL_ERROR` envelope for unexpected failures. | The spec does not define one; leaking internals is worse than a generic copy. | 500 responses are stable and non-sensitive. |
| D-7 | 2026-11-18 | Quote derivation ignores provider-supplied `d`/`dp` when `previousClose` exists. | Spec §4.2 defines change in terms of price and previous close; deriving once prevents provider disagreement. | When `previousClose` is absent, change is `0` and percent is `null`. |
| D-8 | 2026-11-18 | Last known observation is served only while younger than 15 minutes. | §7 says cached data is served regardless of provider availability; staleness still has to be honest. | Failed refreshes keep an honest, marked quote for up to 15 minutes, then `Price unavailable`. |
| D-9 | 2026-11-18 | Quotes are fetched with bounded concurrency (8 workers) per batch. | 60 tickers at a 2 s timeout must not serialise into two minutes. | Order is preserved in the response; per-ticker failure stays isolated. |
| D-10 | 2026-11-18 | Chart is rendered client-side from `/api/chart/:ticker`; the SPA shell is served for `/chart/*`. | One router, one data path, deep links work on refresh. | Go only needs an `index.html` fallback for non-API paths. |
| D-11 | 2026-11-18 | `/api/quotes` returns `502 PROVIDER_UNAVAILABLE` only when no quote was served and a ticker failed on a provider error. | SCN-047 asserts 502; the spec's endpoint table lists only 503, so the trigger is kept narrow. | Partial batches stay 200, rate limits stay 429, unknown-only batches stay 200. |
| D-12 | 2026-11-18 | Symbol verification for an add runs before the store lock is taken. | Holding the store mutex across a 2 s provider call would block the watchlist for every request. | Duplicate check happens twice: cheap pre-check, authoritative re-check inside `Update`. |
| D-13 | 2026-11-18 | No remove control in the UI; removal stays API-only. | Follows the user decision recorded as D-8 in the reference run: no UI scenario depends on removal and there is no approved copy/confirmation. | `DELETE` is complete, tested and documented in contracts §3. |
| D-14 | 2026-11-18 | A last-known quote is served for up to 15 minutes while providers are down. | Spec §7 says cached data is served regardless of provider availability; the 15-minute stale window keeps it honest. | SCN-022's `Price unavailable` holds with the cold cache that the scenario's background defines; an older observation is omitted. |
| D-15 | 2026-11-18 | The missing-key gate runs before the watchlist is read. | The startup message naming both variables is more actionable than an empty state that cannot be used until keys exist. | A keyless first run shows the key message; an empty watchlist with keys shows the empty state. |
| D-16 | 2026-11-18 | A malformed `/api/chart/{ticker}` path returns `400 INVALID_TICKER`. | It is a malformed request, not a provider answer. The frozen chart table only enumerates range and availability errors, so this is documented as an additional engineering case. | The chart page renders the returned copy verbatim. |
| D-17 | 2026-11-18 | Quote timestamps render as `dd-MMM-yyyy` in UTC, plus ` (stale)` when stale. | Product-owner request; the API still emits ISO-8601 and `<time dateTime>` keeps it machine-readable. | Display-only deviation from SCN-023's ISO text; unit tests assert the new format. |
| D-18 | 2026-11-18 | One owner account, created by a first-run setup. No public registration after setup. | The product scope is a local single-user tool; adding multi-tenant storage would be a larger redesign with no acceptance coverage. | Superseded by D-34: any number of accounts, each with a separate watchlist and its own session. |
| D-19 | 2026-11-18 | TOTP is mandatory; recovery codes are the only fallback. No email/SMS reset. | Email delivery is out of scope and the app has no SMTP configuration. Ten single-use codes cover lost-authenticator recovery. | Losing both the authenticator and all recovery codes requires deleting that account's row from `stock-dashboard.db`; its recovery codes and watchlist rows cascade. |
| D-20 | 2026-11-18 | Sessions live in memory and use hashed 256-bit tokens in `HttpOnly` cookies (12 h absolute, 30 min idle). | A restart invalidating sessions is acceptable for a local tool and avoids persisting bearer tokens. | Users sign in again after a restart; tokens never appear in JSON or browser storage. |
| D-21 | 2026-11-18 | Argon2id with 64 MiB, t=3, p=4, 16-byte salt, 32-byte key. | Current OWASP-aligned defaults; tunable in tests through options. | Login costs roughly 100 ms of CPU, which is acceptable for one local user. Superseded by D-42: new hashes use PBKDF2-HMAC-SHA256; Argon2id remains only for legacy verification. |
| D-22 | 2026-11-18 | TOTP is SHA-1/6 digits/30 s/±1 step with persisted replay rejection; 5 password failures/15 min and 5 code attempts per challenge. | Compatible with every authenticator app and blocks replay and online guessing. | A code can be used once per time step; the UI accepts the next code after 30 s. |
| D-23 | 2026-11-18 | `users.json` is a new persisted file; `watchlist.json` is unchanged. | Keeps the existing data format and migration risk at zero. | Superseded by D-33: accounts and watchlists persist in `stock-dashboard.db`, not JSON. |
| D-24 | 2026-11-18 | Unsafe `/api` methods check `Origin` when present; auth and watchlist POST require JSON when a content type is present. | Together with `SameSite=Strict` this closes cross-site request forgery without breaking CLI/tests that omit Origin. | Cross-site browser calls are rejected with `403 CROSS_ORIGIN_REQUEST`. |
| D-25 | 2026-11-18 | First-run setup is pending in memory and persists only after TOTP activation. | An interrupted setup must not leave a half-created account with no usable second factor. | Reloading setup discards the previous secret and recovery codes; restarting setup is safe. |
| D-26 | 2026-11-18 | Setup and activation are serialised by one mutex; `Host` must be `127.0.0.1`, `localhost` or `::1`. | Closes a concurrent-setup race and DNS-rebinding access from a hostile web page. | New setups wait for an in-flight activation; non-loopback Hosts get `403 CROSS_ORIGIN_REQUEST`. |
| D-27 | 2026-11-18 | A 60-second login block does not clear the 15-minute failure window. | Keeps the documented "5 failures / 15 minutes" budget instead of silently resetting to 5/minute. | A fresh burst after the block re-blocks; successful login still clears the window. |
| D-28 | 2026-11-18 | The Vite dev proxy uses `changeOrigin: false`. | The Go CSRF guard compares `Origin` with `Host`; rewriting `Host` to the API port would reject every dev mutation. | Login/setup through `:5173` passes the same origin check as `:3000`. |
| D-29 | 2026-11-18 | `/` is a public landing page; the dashboard moved to `/dashboard`. | The product owner asked for a landing default with unauthenticated redirects to login. | Anonymous visitors see the landing CTA; protected pages redirect to `/login` and return to the requested path after sign-in. First-run still goes to `/setup`. |
| D-30 | 2026-11-18 | The landing CTA is always `Sign in`; the first-run `Set up your account` action lives only on `/login`. | Product-owner request: the welcome page stays a welcome page, and sign-up is discovered on the sign-in page. | Superseded by D-34 for the account prompt: `/login` always shows `New here? Set up your account` and it always opens account creation. The UI never states whether any account exists. |
| D-31 | 2026-11-18 | Passwords require a 12-character minimum and have no user-facing maximum. | Product-owner request to keep the rule to "just 12 length min"; the 4 KiB request body cap bounds input. | The UI removes `maxLength`; the server accepts long passwords. This supersedes the frozen plan's 12–128 wording; the plan itself is unchanged. |
| D-32 | 2026-11-18 | `New here? Set up your account` is always visible on `/login`; `/setup` after setup shows a closed notice. | Product-owner request for a permanent sign-up option, while keeping the single-owner invariant. | Superseded by D-34: `/setup` is the open Create account page; the closed notice and the single-owner invariant are removed. |
| D-33 | 2026-11-18 | Persist watchlist, owner and recovery hashes in `$DATA_DIR/stock-dashboard.db` (SQLite) instead of JSON files. | Product-owner request; transactions remove the multi-file consistency window and one file is easier to back up. | `modernc.org/sqlite` (pure Go, no CGO); legacy JSON is imported once and renamed `.migrated`; sessions stay in memory. Supersedes the frozen plans' JSON file expectations. |
| D-34 | 2026-11-18 | Multiple accounts, each with its own watchlist. Registration is always open from `/login`. | Product owner removed the single-owner limit and chose separate watchlists. | Schema v2 scopes `watchlist.user_id`; sessions carry the account ID; the existing owner keeps AAPL; new accounts start empty. Supersedes the single-owner parts of the frozen plans. |
| D-35 | 2026-11-18 | Ship a multi-stage minimal image; container sets `BIND_HOST=0.0.0.0` and publishes only on host `127.0.0.1`. | Product-owner request. A loopback bind inside a container is unreachable from the host, while exposing 0.0.0.0 on the host would violate the local-only rule. | The image runs nonroot on Alpine 3.23 with `ca-certificates`, BusyBox and `apk`; the two static Go binaries and `/data` are added. No source, tests, `node_modules` or tzdata are added. Keys are runtime env only; a bundled raw-socket healthcheck probes `/healthz`. |
| D-36 | 2026-11-18 | Authorisation is a public allowlist plus a per-route session wrapper, not a protected-path blocklist. | A blocklist fails open when a new `/api` route is added and nobody updates a second switch. | Every `/api` route in the router table is explicit public or wrapped; a test walks the table and a deny-all auth stub asserts 401. `/healthz` and the documented auth endpoints stay public. |
| D-37 | 2026-11-18 | Password/TOTP attempts are reserved before verification; setup/login share a global per-minute budget and a small password-hash semaphore; hashing never runs under `setupMu`; session authentication uses the immutable session entry and pruning is amortised. | Concurrent bursts bypassed the 5-attempt caps and one auth mutex held across SQLite I/O could freeze every session. | Second concurrent setup returns `429` instead of queueing; the password cap holds under parallel requests; `auth.Service.mu` is never held across store I/O; lock order is `setupMu -> mu -> (released) -> store.mu`. |
| D-38 | 2026-11-18 | Provider failures are normalised: upstream `429` -> `RATE_LIMITED` with `Retry-After`, `401/403` -> credential failure (`MISSING_API_KEY`), cancellation distinct from outage, one jittered retry for transient idempotent GETs. | Collapsing throttling, bad keys and cancellation into `502` gave users the wrong copy and made operator diagnosis harder. | No provider text leaves the adapter; timeouts stay bounded at one attempt; a cancelled batch is never a clean empty `200`. |
| D-39 | 2026-11-18 | `ALLOWED_HOSTS`, provider RPM, upstream timeout and quote cache TTL are validated environment settings; production limits live once in `providers.DefaultLimits`; shutdown drains for `WriteTimeout + 5s`. | Host policy and quota tuning required a rebuild, and the 10 s drain was shorter than the 60 s write timeout. | Defaults preserve current behaviour; `recoverMiddleware` wraps `hostGuard` so panics still produce the envelope; an orderly restart no longer fails under a slow request. |
| D-40 | 2026-11-18 | Store reads never fail silently: bounded warnings name only the operation, account reads fail closed after a 30 s grace window, `FindByID` no longer loads recovery hashes, and watchlists serve the maintained snapshot (first read loads, writes refresh). | A permanent storage fault previously looked healthy forever, and the polling path paid two extra SQL round trips per request. | Corrupt/unreadable account tables stop authenticating; display data keeps its last known value with a warning; the hot path stays off the single SQLite connection. |
| D-41 | 2026-11-18 | API hardening: malformed `DELETE /api/watchlist/{ticker}` is `400 INVALID_TICKER`; bodies over 4 KiB are `413 REQUEST_TOO_LARGE`; `writeJSON` keeps the error envelope on marshal failure; the status recorder unwraps and recovery does not append to a partial response; recovery-code scans do not early-exit. | Path text was echoed into user copy, oversize bodies looked like malformed tickers, and a late panic could corrupt a response. | Well-formed non-members still return `404 NOT_IN_WATCHLIST`; small malformed bodies keep their domain copy; all comparisons still run in constant time over the whole set. |
| D-42 | 2026-11-19 | New password hashes use PBKDF2-HMAC-SHA256 with 600,000 iterations; legacy Argon2id hashes still verify and are rehashed after a successful password login. | Product owner chose a low-memory KDF to remove the 64 MiB-per-hash OOM amplification; PBKDF2 stays deliberately CPU-hard. | No password-length limit; the existing per-minute budget and verification semaphore still bound hashing work; Argon2 code remains only for legacy verification until accounts rehash. |
